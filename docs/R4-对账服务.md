# R4 对账服务 reconcile-service · 实现与验收文档

> 需求出处：差距文档 R4（订单侧 vs 库存侧流水 diff + 台账状态机）
> 代码：`internal/reconcile/` · 服务入口：`cmd/reconcile-service`（`:8089`）

---

## 一、定位：对账不是监控，是兜底

本服务与 R1-3 的 Redis/DB 对账互补，覆盖两个视角：

| 对账 | 视角 | 代码 |
|------|------|------|
| R1-3 | 加速层 vs 真账（Redis 预扣流水 vs stock_journal） | `internal/inventory/reconcile.go` |
| **R4（本服务）** | **业务单据 vs 库存凭据（orders vs inventory_reserved）** | `internal/reconcile/` |

差异统一写入 `reconcile_diff` 台账（R1 已建表，`biz_type` 区分：STOCK / ORDER_INV）。

## 二、双向 diff 语义

**方向 A · ORDER_NO_RESERVATION**：订单持有占库存状态
（RESERVED/PROCESSING/SUCCESS）但 `inventory_reserved` 无该订单记录
——订单声称占了库存，库存侧却没有凭据（预占写失败/被误删）。

**方向 B · RESERVATION_ORPHAN**：库存侧仍持有预占（status=RESERVED）
但订单已终结（CANCELED/FAILED）或不存在——幽灵占用，库存被无主扣减。

## 三、台账状态机

```
PENDING ──resolve──► RESOLVED（已修复）
    │
    └──ignore───► IGNORED（误报/暂不处理）
```

- 终态不可逆：流转 UPDATE 带 `WHERE status='PENDING'`，
  affected=0 即 `ErrInvalidTransition`（测试覆盖）。
- 差异登记 `INSERT IGNORE` 幂等：同一差异只记一次，不产生重复工单。

## 四、端点与服务

| 端点 | 说明 |
|------|------|
| `POST /reconcile/run` | 手动触发一轮对账，返回 `{orders_checked, orphans_found, new_diffs}` |
| `GET /reconcile/diffs?status=PENDING&limit=50` | 台账查询 |
| `POST /reconcile/diffs/:id/resolve` | 关闭差异 |
| `POST /reconcile/diffs/:id/ignore` | 忽略差异 |

服务内置每 5 分钟自动对账；`/healthz /readyz /metrics` 齐备；K8s YAML 已加。

## 五、验收（手工造差异演示）

```bash
go run cmd/reconcile-service/main.go

# 1. 造差异：把一条 RESERVED 订单的预占记录删掉
mysql> DELETE FROM inventory_reserved WHERE order_id = 'O-DEMO';

# 2. 捕获
curl -X POST localhost:8089/reconcile/run
# => {"code":0,"data":{"orders_checked":1,"orphans_found":0,"new_diffs":1}}

curl 'localhost:8089/reconcile/diffs?status=PENDING'
# => [{..."diff_type":"ORDER_NO_RESERVATION","request_id":"O-DEMO"...}]

# 3. 修复后关闭
mysql> INSERT INTO inventory_reserved(reserved_id, order_id, status, ...) VALUES (...);
curl -X POST localhost:8089/reconcile/diffs/1/resolve
# => {"status":"RESOLVED"}

# 4. 重复 resolve 被状态机拒绝（40401）
```

单测对应 `internal/reconcile/service_test.go`：双向 diff、clean 零差异、
resolve/ignore/非法流转、handler 全链路。

## 六、与真实经历的差异（诚实红线）

| 真实经历 | 本练习仓简化 |
|---|---|
| 对账双写台账系统 + 告警联动 + 自动修复动作 | 单表台账 + 手动/自动关闭，无告警联动 |
| 按小时分区滚动清理 | 无清理（复用 R1 台账，后续统一补） |

## 七、面试话术锚

「对账不是监控是兜底——差异进台账状态机直到关闭；订单/库存双向 diff，
一个查有单无据，一个查有据无单，INSERT IGNORE 保证差异工单不重复。」
