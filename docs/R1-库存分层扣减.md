> 实现日期：2026-10-25 · 代码：`internal/inventory/prestock.go` / `stocksync.go` / `reconcile.go`

## 一、设计：叠加层而非替换

现有 inventory-service 的 TCC 三段式（`Reserve/Confirm/Release`，DB 事务 + reserved_id 追踪）**保持不变**，
订单主链路继续走它。R1 新增 Redis 预扣加速层，面向高并发场景（秒杀/抢购）：

```
请求 ──► Lua 原子四步（读、判、扣、记）──► Redis
                                          │  prestock:avail:{sku}   剩余额度
                                          │  prestock:log:{sku}     未落库流水(hash)
                                          ▼
                              stock-sync worker（异步落库）
                                          │  事务: INSERT IGNORE stock_journal (uk: sku+request)
                                          │       + UPDATE inventory.available
                                          ▼
                                     DB 真账
                                          ▲
                              reconciler（对账兜底）
                                          │  Redis 流水 vs stock_journal 差集
                                          ▼
                              reconcile_diff 台账（PENDING → RESOLVED）
```

**一句话**：预扣是加速层不是真账；真账在 DB，对账兜底。

## 二、关键语义

| 语义 | 实现 |
|------|------|
| 原子扣减 | Lua 脚本内完成读额度→判幂等→判足量→扣减→记流水，单脚本原子 |
| 幂等重放 | 同一 `request_id` 再次预扣返回 `DUPLICATE`，额度不重复扣（Lua HEXISTS 前置判断） |
| 额度初始化 | 首次预扣时从 DB `inventory.available` 惰性加载（SETNX 防并发重复初始化）；演示可 `POST /inventory/prestock/init` |
| 异步落库 | `SyncOnce` 按 request_id 排序遍历流水，事务内 `INSERT IGNORE stock_journal`，**仅新插入成功才扣真账**，随后清理 Redis 流水 |
| 重投吸收 | 崩溃后流水残留/重投 → journal 撞唯一键 → affected=0 → 不再扣减（at-least-once 落库 + 唯一键 = 恰好一次扣减） |
| 归还 | `Restore` Lua：流水存在才加回额度并删除（防双重归还） |
| 对账宽限 | 流水超过 30s（`reconcileGrace`）未落库才判差异，避免把在途同步误报 |

## 三、与真实经历的差异（诚实红线）

| 真实经历（A 公司） | 本练习仓简化 |
|---|---|
| 预扣结果写 Redis hash + 异步刷 MySQL 流水表，按分钟级批量 | 同构；批量粒度为 1s tick，未做自适应批量 |
| 对账 job 比对双端流水差集并推动修复闭环 | 同构最小版：差集进台账 + 手动/自动关闭 |
| 库存中心独立服务、多商品域分片 | 单 inventory-service 内分层，未拆独立预扣服务 |

## 四、测试矩阵（`internal/inventory/prestock_test.go`）

**R1-1 预扣**
- `TestPreStockReserve_ConcurrentNoOversell`：1000 并发扣 100 → granted=100、rejected=900、avail=0、流水=100（**零超卖零少卖**）
- `TestPreStockReserve_IdempotentReplay`：同 request_id 重放 → DUPLICATE，额度只扣一次
- `TestPreStockReserve_Insufficient`：不足 → INSUFFICIENT，不留流水
- `TestPreStockReserve_LazyInitFromDB` / `_MissingSKU`：惰性初始化与 SKU 不存在

**R1-2 落库**
- `TestStockSync_PersistsAndClears`：流水落库 + 真账扣减 + Redis 清理
- `TestStockSync_DuplicateDeliveryAbsorbed`：重投被唯一键吸收，真账不重复扣（先写失败测试再实现）

**R1-3 对账**
- `TestReconcile_DetectsUnsyncedEntry`：超宽限未落库 → 台账 REDIS_NOT_SYNCED；宽限内不误报
- `TestReconcile_CleanWhenAllSynced`：全落库 → 零差异
- `TestReconcile_ResolveDiff`：台账关闭

测试基建：miniredis（真实执行 Lua）+ sqlmock，连跑 5 次稳定。

## 六、面试话术锚

「预扣用 Lua 四步原子（读判扣记），真账在 DB，对账兜底——预扣是加速层不是真账。
崩溃恢复靠 at-least-once 落库 + 流水唯一键幂等吸收；对账差异进台账状态机直到关闭。」
